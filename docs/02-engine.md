# 02 · 엔진 (3층 로직 · LLM 호출 · API 규격)

> 상위: `core.md`. 이 문서는 제품의 심장이다. 가장 신중하게 구현하라.

## 2.1 엔진 3층 (개념)

```
[1층] 의도측정·라우터
   입력: 유저 한두 줄
   처리: 의도 1차 추론 → "결과물 형태" 후보 상상 → 그것들을 가장 크게 가르는
         객관식 질문 최대 3개 생성 (정보이득 최대화)
   출력: intentGuess + questions[]

[2층] 모듈 분기
   입력: 유저의 객관식 답변
   처리: 결과물 형태 확정 → 모듈 라우팅 (MVP: 1개 모듈만 존재)
   라우팅 애매하면 → 추가 질문 1개만 더

[3층] 전문가 체인 (모듈 내부)
   처리: 프롬프트 전문가 + 도메인 전문가 관점 결합
        (분야가 'A에 대한 B' 형태면 도메인 전문가 2분할
         예: 상세페이지 → 상세페이지 제작 전문가 + 해당 상품 전문가)
   출력: 최종 실전 프롬프트 1개
```

## 2.2 질문 생성 규칙 (1층 — 품질의 핵심)

연구 근거: Bayesian Experimental Design / Expected Information Gain.

- 질문 전에 **"이 입력으로 나올 수 있는 결과물"을 3가지 이상 내부적으로 상상**하고,
  그것들을 가장 잘 가르는 분기를 질문으로 만든다. (질문만 고민하지 말 것)
- **넓은 것 → 좁은 것** 순서(funnel). 형태 먼저, 세부 톤은 나중.
- 각 질문에 2~4개 객관식 보기. **보기 자체가 친절한 설명**이 되게 한다.
- 질문은 **최대 3개**. 안 물어도 되는 건 묻지 마라.
- 마지막에 "기타: 직접 입력" 여지를 둔다.
- 불필요하면(의도가 이미 명확하면) 질문을 건너뛰고 바로 3층으로.

## 2.3 LLM 호출 분리 (비용·지연 관리)

| 호출 | 모델 | 목적 |
|------|------|------|
| 1층 (`/api/intent`) | `LLM_MODEL_INTENT` (저비용) | 의도측정 + 질문생성 |
| 3층 (`/api/generate`) | `LLM_MODEL_GENERATE` (고품질) | 최종 프롬프트 생성 |

- 모든 호출 후 `usage_logs`에 model·inputTokens·outputTokens·latencyMs 기록.
- LLM 호출 래퍼는 `lib/llm/` 에만 둔다. 다른 곳에서 직접 fetch 금지.

## 2.4 API 입출력 규격

### POST /api/intent
```jsonc
// 요청
{ "inputText": "만두 메뉴 이미지", "locale": "ko" }

// 응답
{
  "sessionId": "abc123",
  "intentGuess": "음식점 메뉴용 만두 이미지로 추정",
  "needsQuestions": true,
  "questions": [
    {
      "id": "q1",
      "text": "이 이미지를 어디에 쓰나요?",
      "options": ["배달앱 썸네일", "매장 메뉴판", "인스타 피드", "기타: 직접 입력"]
    }
    // 최대 3개
  ]
}
```

### POST /api/generate
```jsonc
// 요청
{
  "sessionId": "abc123",
  "answers": [{ "id": "q1", "value": "매장 메뉴판" }],
  "locale": "ko",
  "outputLang": "ko"   // 생성 프롬프트 언어(UI 언어와 별개)
}

// 응답
{
  "routedModule": "image_detail",
  "finalPrompt": "....(복사용 완성 프롬프트)....",
  "assumptions": ["배경색은 화이트로 (자동설정)"],
  "editHint": "상품 실제 색상을 직접 지정하면 더 정확합니다"
}
```

> ⚠ 1층은 반드시 **questions만 반환하고 멈춘다.** 한 번에 끝까지 생성하지 마라.
> 유저 답변(`/api/generate`)이 와야 3층을 실행한다.

## 2.5 프롬프트 자산 위치

- 1층·3층의 실제 시스템 프롬프트 문구는 `lib/engine/prompts/` 에 분리 저장.
- 베이스 설계는 별도 파일 `의도추론엔진_v1_단일프롬프트.md`(이 대화 산출물)를
  서버용으로 단계 분리해 옮긴 것이다. 한 덩어리 프롬프트를
  `intent` / `generate` 두 호출로 쪼개서 사용한다.

## 2.6 도메인 지식 안전장치 (환각 방지)
- 도메인 전문가 역할이 **구체 사실(수치·성분·규격)을 지어내지 못하게** 한다.
- 유저 입력으로 채우되, 비면 `(자동설정)`/`(확인필요)` 표시.
- 필요 시 향후 RAG(검색증강) 연동 자리를 남겨둔다(2차).
